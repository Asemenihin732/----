# X-Lance · Деловая игра «Спаси конференцию!»

Веб-приложение для деловой игры по методичке фасилитатора (версия 4.0): команды ведут
проекты конференции PMFest 2026, открывают карточки проблем и влияют на три KPI —
**срок, маржинальность и удовлетворённость заказчика**. В конце — табло с индексом проекта.

## Запуск

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # production-сборка
npm run test:engine # формула индекса из методички + переходы по командам
npm run test:data   # целостность колод и бюджетов
npm run test:smoke  # рендер маршрутов (headless Edge, на фоне vite preview)
```

Демо-сессия из двух команд и двух раундов: откройте `/?seed=1`.

## Как идёт игра

0. **Вход (`/login`)** — авторизуемся в X-Lance (email + пароль).
1. **Старт (`/`)** — выбираем число раундов (1–3) и число команд (1–6); при необходимости
   жмём «Создать в X-Lance» (развёртывание тенанта, проектов-команд, задач и ресурсов), затем «Аппрув».
2. **Экран команды (`/team/:id`)** — по очереди для каждой команды:
   - сверху — метрики в блоках: индекс проекта, срок, маржинальность, удовлетворённость;
   - ниже — диаграмма Ганта проекта, справа стоимость каждого ресурса, ещё ниже — блок финансов;
   - снизу — четыре перевёрнутые карточки. Выбираем **ровно одну**: она разворачивается
     в блок с вариантами решения вместо четырёх карт.
3. **Аппрув решения** — кнопка фиксирует решение (меняются срок, расход, доход и
   удовлетворённость) и ведёт к следующей команде; после последней команды последнего
   раунда — к итогам.
4. **Итоги (`/results`)** — табло с местами и номинации.

## Авторизация и развёртывание в X-Lance

Приложение работает с реальным X-Lance по GraphQL (`VITE_XLANCE_API_URL`, по умолчанию
`https://preview.x-lance.ru/api/graphql`).

1. **Вход** (`/login`) — email и пароль, мутации `signIn` / `signUp`. Токены
   (`access_token`, `refresh_token`) хранятся в `localStorage`, при истечении
   access-токен молча обновляется через `refreshToken`. Все внутренние маршруты
   закрыты гардом: без входа — редирект на `/login`.
2. **Развёртывание** — на экране настройки (`/`), блок «3. Развернуть в X-Lance»:
   - находит или создаёт тенант (`createTenant` / `myTenants`) и проверяет права (`myAccess`);
   - берёт дефолтные справочники тенанта (`objectTypes`, `objectStatuses`);
   - на каждую выбранную команду создаёт **проект** (`createProject`, код = id команды в верхнем регистре);
   - создаёт **задачи работ** из плана (`X-Lance_Plany_rabot.xlsx`) как
     самостоятельные задачи проекта — **без родительской (суммарной) задачи**;
   - задаёт **связи предшествования** (`predecessors`, типы FS/SS/… с лагом) и
     **трудозатраты** (`assignments.planWork`, часы: чел.-дн. × 8), поэтому X-Lance сам
     пересчитывает срок и загрузку: длительность — через `duration`, даты — по связям;
   - создаёт **трудовые и материальные ресурсы** из таблицы ресурсов плана
     (`createResource`, `createProjectResource`) и сразу заводит **стоимость
     трудовых ресурсов** (`createCostRate`, ставка за час = дневная ставка ÷ 8).
   Повторный запуск идемпотентен: проекты ищутся по коду, ресурсы — по имени,
   существующие задачи приводятся к плану (`updateTask` — связи, трудозатраты),
   устаревшая «главная» задача удаляется (`deleteTask`).

Развёртывание можно выполнить и из консоли:

```bash
XL_EMAIL=... XL_PASSWORD=... npm run provision
# опционально: XL_TENANT, XL_TENANT_KEY, XL_TEAMS=catering,stage,...
```

## Вход участников по ссылке (`/join`)

Страница `/join` открыта без входа (из меню пока не ведём — пункт в сайдбаре закомментирован).
Участник вводит ID (ключ) тенанта и почту, ссылка `/join?tenant=IG` подставляет тенант заранее.

Гость сам себя пригласить не может — `inviteHumanResource` требует прав админа тенанта,
поэтому приглашает сервер (`server/join.ts`, `POST /api/join`) от служебного аккаунта:
находит человека-ресурс с этой почтой (нет — создаёт), добавляет его во все проекты тенанта
с проектной ролью (по умолчанию «Наблюдатель» `PROJECT_VIEWER` — видит проекты и работы, ничего
не меняет; роль тенанта «Участник» прав на проекты не даёт) и приглашает с ролью участника.
Если человек уже состоит в проекте, роль дописывается к его ролям; при повторном входе
добавляются новые проекты.
Эндпоинт работает в `npm run dev` и `npm run preview`; на статическом хостинге `/api/join`
и `/api/admin/join-tenants` не работают — в продакшне игру отдаёт Node-сервер (`server/serve.ts`).

**Продакшн-запуск** (Node 20.12+, без лишних зависимостей):

```bash
npm run build && npm run build:server && npm run serve
```

`build:server` собирает сервер esbuild'ом в `dist-server/serve.mjs`, `serve` запускает его.
Сервер раздаёт `dist/` (пути без файла — на `index.html`, так что `/join` и `/admin`
открываются напрямую), монтирует `/api/join` и `/api/admin/join-tenants`, читает
окружение из `.env` (`.env.production.local`, `.env.local`, `.env.production`, `.env` —
как Vite; переменные процесса важнее). Порт — `PORT` (по умолчанию 8080), каталог сборки —
`DIST_DIR` (по умолчанию `dist`); пути, в том числе `XL_JOIN_STORE`, считаются от каталога
запуска. Без служебного аккаунта или открытых тенантов `POST /api/join` отвечает 503
«Вход по ссылке не настроен.». За обратным прокси (nginx и т. п.) достаточно проксировать
всё на этот порт.

**Куда открыт вход** настраивает фасилитатор в **Админке** (`/admin`, пункт в сайдбаре):
выбирает свой тенант → «Открыть вход», копирует ссылку `/join?tenant=<ключ>` или показывает
QR-код под ней (клик — крупно на весь экран, для проектора; Esc закрывает), при
необходимости закрывает вход. Ссылка живёт `XL_JOIN_INVITE_TIME` с момента открытия:
по истечении участники видят «вход закрыт», а в админке тенант остаётся с пометкой
«срок истёк» — кнопка «Продлить» отсчитывает срок заново. QR-код и ссылка строятся от адреса,
по которому открыта админка, — открывайте её по публичному адресу игры. Сервер проверяет токен фасилитатора в X-Lance: менять
список можно только по тенантам, где он админ. Рядом виден статус служебного аккаунта
(админ ли он в тенанте). Список хранится на сервере в `XL_JOIN_STORE`
(по умолчанию `.data/join-tenants.json`, в git не попадает).

| Переменная          | Назначение                                                            |
| ------------------- | --------------------------------------------------------------------- |
| `XL_JOIN_EMAIL`     | служебный аккаунт — админ игровых тенантов                              |
| `XL_JOIN_PASSWORD`  | его пароль (без `VITE_` — в бандл не попадает)                          |
| `XL_JOIN_STORE`     | файл списка открытых тенантов (по умолчанию `.data/join-tenants.json`)  |
| `XL_JOIN_ROLE`      | код роли тенанта для участника (по умолчанию `TENANT_MEMBER`)           |
| `XL_JOIN_PROJECT_ROLE` | код или название проектной роли во всех проектах (по умолчанию `PROJECT_VIEWER`; `none` — не добавлять) |
| `XL_JOIN_INVITE_TIME` | сколько живёт ссылка после открытия: `90m`, `12h`, `3d`, число — минуты; по умолчанию `24h`, `0` — без срока |

Ограничение: 10 попыток с одного IP за 10 минут.

```

│   ├── graphqlApi.ts     # тенанты, справочники, проекты, задачи, ресурсы

│   ├── api.ts            # клиент X-Lance: Ганта, ресурсы, финансы, показатели, отчёты
│   ├── config.ts         # .env, маппинг «Действие в X-Lance»

│   └── types.ts          # DTO X-Lance
├── data/                 # методичка: 6 планов, 81 карточка, хронометраж, номинации
│   ├── projects.ts       # описания команд (works, бюджет) для игры
│   └── plan.ts           # планы работ из X-Lance_Plany_rabot.xlsx: связи, ресурсы, трудозатраты

│   ├── engine.ts         # KPI и индекс проекта, ранжирование, номинации

│   └── types.ts
├── components/           # Layout, Ганта, общие элементы
└── pages/                # Вход · Старт · Экран команды · Итоги
```

## Модель расчёта

- **KPI Срок** = база ÷ факт × 100; **KPI Маржа** = факт % ÷ базовый % × 100
  (при отрицательной марже — 0); **KPI Удовлетворённость** — значение на конец игры (40–130 %).
- **Индекс проекта** = среднее арифметическое трёх KPI.
- Данные Ганты, ресурсов и финансов экран тянет через `api.*` (REST-разделы методички);
  решения команд уходят в X-Lance через GraphQL (`updateTask`, показатель удовлетворённости).
